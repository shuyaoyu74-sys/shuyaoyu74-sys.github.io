Agent定义与原理

定义

OpenAI 将通向通用人工智能（AGI）之路分为五个等级，这决定了技术进化的终极目标。

  1. Level 1: 聊天机器人 (Chatbots) - 具备自然语言交互能力（如基础款 ChatGPT），能聊天但执行力弱。
  2. Level 2: 推理者 (Reasoners) - 能够解决人类水平的问题，具备深度的逻辑推理。
  3. Level 3: 智能体 (Agents) - 核心分水岭。它不仅能思考，还能在长达数天的时间内自主执行任务、做决策并采取行动。
  4. Level 4: 创新者 (Innovators) - 能够产生新的知识和科学发现。
  5. Level 5: 组织者 (Organizers) - 能够像一个组织一样独立完成复杂的、高价值的协作任务。

Agent 为能够感知环境、自主决策、主动行动和学习进化的 AI 程序。它模仿了生物的反馈机制：

  • 感知 (眼睛)：通过传感器（摄像头、麦克风、API 接口）获取环境数据。
  • 决策 (大脑)：基于数据和逻辑进行判断（如深度学习、强化学习）。
  • 执行 (手)：通过机械臂、软件指令（发邮件、写代码、调接口）产生后果。
  • 学习 (进化)：通过反馈优化算法，不断迭代提升效率。

传统的软件是“输入 A 得到 B”，而 Agent 是“根据当前情况 A，决定做 B，如果 B 失败了再尝试 C”。这种自主性是其核心价值。

Agent 的概念并非新事物，它经历了三个主要阶段：

  1. 规则驱动/符号驱动 (1960s-1990s)：基于“IF-THEN”逻辑。局限：只能处理预设好的、简单明确的环境。
  2. 强化学习驱动 (1990s-2010s)：通过试错学习（如 AlphaGo）。局限：在特定博弈环境很强，但缺乏通用常识和自然语言交互。
  3. 大模型驱动 (LLM-based Agents, 2023年至今)：以大模型为大脑。突破：拥有了海量的常识、逻辑推理能力和理解人类复杂指令的能力。

LLM 的出现解决了 Agent 过去最难解决的两个问题：语义理解（听懂要干嘛）和逻辑规划（知道分几步走）

与其讨论 Agent，不如讨论 Agentic

这是一个非常前沿的观点：智能体不是一种“全或无”的状态，而是一个“光谱”。

系统中具备的智能体属性程度，被称为 Agentic（智能体化程度）。图中借用 LangChain 的分类将其分为 6 个等级：

  1. Human Driven (完全人控)：纯代码，没有 LLM 介入。
  2. LLM Cell：LLM 只负责处理单步指令（如翻译一句话）。
  3. Chain (链式)：多步固定流程，LLM 负责每一环。
  4. Router (路由)：LLM 具备了一点点判断力，决定接下来走哪条路径。
  5. State Machine (状态机)：具备循环和逻辑判断，直到达成某个状态。
  6. Autonomous (自主智能体)：最强级别。系统能自主选择工具、具备记忆、并能自我纠错。

现实中很多应用并不需要 100% 的自主（太危险或不可控），开发者应该根据场景选择合适的“智能体化程度”。例如，自动驾驶 L1-L4 的逻辑同样适用于 AI 系统。

LLM Agent原理

我们可以把 Agent 理解为一个拥有“大脑”的数字员工。大模型充当其推理的大脑，它并不直接执行每一个操作，而是指挥和协调整个系统。

整个智能体架构的核心可以总结为以下四个核心组件：

1、大脑llm

实现语义理解，常识推理，规划指令等

2、工具使用

它允许 Agent 通过一套 API、脚本或应用程序接口来感知外部世界，并与其进行交互。通过调用搜索 API 网页检索、调用数据库查询 API，让 Agent 能够“读”和“听”到外部世界的实时信息。通过代码执行解释器、网页自动化工具、社交媒体 API（如发推、发邮件），让 Agent 能够产生可观测的行动后果，而不仅仅是说。

3、规划

对于复杂的长期任务，大脑不能像简单的问答那样一次性完成，必须经过严密的规划。这可以分为两个主要阶段：

A. 任务分解

大脑会把一个复杂的大目标拆解为可执行的小步骤。

  • 思维链 (Chain of Thought, CoT): 这是最基本的规划方法。它指示 LLM 不要直接跳到答案，而是先生成一连串连贯的思维步骤，通过逐步推理来解决问题。
  • 思维树 (Tree of Thoughts, ToT): 在 CoT 的基础上，它允许 Agent 在推理过程中产生多个分支（备选方案），并对不同的路径进行自我评估和选择。

B. 自我反思

这是一个关键的反馈循环。Agent 在执行特定动作后，大脑会获得外部世界的反馈（观察结果），然后自我评估动作的成效，并动态调整后续的规划。

  • ReAct (Reason + Act): 这是一个经典的规划模式。Agent 会生成一个思考步骤，明确接下来要做什么以及为什么，然后执行具体的工具动作 ，最后观察动作的结果并开始下一个循环。它将推理和行动紧密交织在一起。

4、记忆

智能体的记忆系统非常关键，它决定了 Agent 能否处理长期任务，并根据过去的经验优化当前决策。

短期记忆

  • 大模型上下文窗口 : 它是大模型自身的“内存”，存储了当前任务中最近一次对话的历史、中间步骤的规划以及所使用的工具所返回的临时信息。它是临时的、有限的，随着对话的进行会被新信息覆盖。

长期记忆

  • 外部知识库: Agent 可以利用外部向量数据库永久存储海量的、结构化的知识。当需要时，它可以通过语义检索技术（RAG）快速调取相关的背景信息，并注入到短期记忆中。
  • 记忆管理： Agent 还需要具备对长期记忆的管理能力：

当 Agent 拥有了长期记忆，能够连接外部知识库时，它在能力上实现了质的飞跃，但也同时面临着一个严峻的工程挑战：检索效率。

想象一下，当我们将海量的文档、业务数据以向量的形式灌入 Agent 的长期记忆库中，大模型在进行思考和规划时，就需要去“回忆”相关的知识。在这个高维向量空间中，寻找与当前问题最相关的记忆，其数学本质就是进行最大内部产品搜索。

然而，在真实的业务场景下，知识库动辄百万、千万级。如果让 Agent 在每次反思时，都去跟数据库里的每一条知识做一遍精确的内积计算（暴力遍历），计算量会引发灾难性的延迟，让原本聪明的 Agent 变得极其迟钝。

为了打破这个检索瓶颈，保证系统的实时反馈，工程实现上必须做出取舍：用少量的精度损失，换取搜索速度的极大提升。这就是近似最近邻算法（ANN）成为 Agent 长期记忆底层标配的原因。

目前主流的向量数据库和 Agent 框架中，主要依赖以下几种核心的 ANN 算法结构来实现高效捞取数据：

  • LSH (局部敏感哈希)：用“碰撞”做聚类 传统的哈希算法是为了防止碰撞，而 LSH 则是故意设计一种特殊的哈希函数，让高维空间中相邻（相似）的向量“撞”进同一个桶中，且桶的数量远小于数据总量。搜索时，只需计算当前输入属于哪个桶，直接在桶内寻找，大幅缩小了关注范围。
  • ANNOY：基于随机投影树的空间切割 它的核心数据结构是随机投影树。每次通过一个随机超平面将高维空间一分为二，直到每个子空间（叶子节点）的数据量足够小。为了提高准确率，通常会构建一个“森林”（多棵独立的树）进行并行搜索，然后聚合结果。它的思想类似传统的 KD 树，但在高维空间的扩展性上表现更优。
  • HNSW (分层可导航小世界)：图结构的检索巅峰 这是目前应用最广、性能极佳的算法之一。它借鉴了社交网络中的“六度分隔”理论，构建了多层的小世界网络。最底层包含所有的实际数据点，越往上层节点越少、“快捷键”跨度越大。检索时，从顶层粗略定位，逐层向下精细导航，完美平衡了跨越距离与搜索质量。
  • FAISS：基于高斯分布的向量量化 FAISS 建立在这样一个假设上：高维空间中的节点距离遵循高斯分布。它通过“向量量化”来实现降维打击，先将庞大的向量空间划分（粗聚类）为若干个集群，然后在每个集群内部再进行更精细的量化。检索时，先锁定潜在的集权候选，再进入候选内部详查。
  • ScaNN：各向异性向量量化的突破 一般的量化算法在压缩数据时，往往只选择绝对距离最接近的质心。但 ScaNN 算法发现，在计算内积时，向量的方向比长度影响更大。因此它采用了“各向异性”的量化策略，使得量化后的向量在方向上尽可能贴近原始向量，极大提升了 MIPS 的最终还原精度。
Question
智能体、LLM、强化学习智能体有啥区别？

和LLM对话：输入一个提示，大模型生成一个回答。

和Agent对话：就像是你有一个助手，助手会先询问你是否进行网络研究，然后写下初稿，然后回顾初稿，并思考哪些部分需要修改，然后修改草稿，不断进行思考和迭代的过程。输入为文字（多模态场景下也会有视觉、语音等信息），策略为预训练的具备世界知识的大语言模型，输出动作为文本，但可以通过结构化输出和提取实现 function_call，进一步与现实环境进行交互。

与强化学习智能体对话： 输入为预设好的向量化的环境状态（或者图像），策略通常由简单的神经网络结构进行初始化，输出动作多为底层控制（移动、攻击等）

Agent分类

按照数量分类

单智能体 (Single Agent)：分为任务导向型（如 AutoGPT、BabyAGI）和角色扮演型。

多智能体 (Multi-Agent)：分为合作型、辩论型和竞争型（竞争型通常基于强化学习）。强调多样化的agent profiles ,agents间交流相互作用与集体决策过程。每个智能体都具有独特的策略和行为，并相互之间进行通信。

按照行为模式分类

  1. Tool Use Agent (工具调用智能体)

此类 Agent 的核心逻辑在于打破大模型“在真空中预测下一个 Token”的局限，将其动作空间扩展至外部 API 和计算引擎。

  • 核心机制：模型不仅输出文本，还输出可解析的工具调用指令。以CRITIC框架为例，其引入了自我修正闭环。

  • 数学逻辑抽象：

    传统的生成为 $y = \text{LLM}(x)$。Tool Use 范式将其转化为一个交互验证过程：

    1. 初始生成：$y_0 = \text{LLM}(x)$
    2. 工具验证：$o = \text{Tool}(y_0)$ （如调用计算器或搜索引擎获取真实反馈 $o$）
    3. 多轮修正：$y_{t+1} = \text{LLM}(x, y_t, o_t)

该范式强调模型对工具返回结果的批判能力。这与我们在构建数据管道时使用 LLM-as-judge 来评估和清洗数据质量的逻辑非常契合，本质都是将 LLM 用作一个具有鉴别能力的仲裁者。典型模型还包括 WebGPT、HuggingGPT 和 Toolformer。

  1. Code Generation Agent (代码生成智能体)

此类 Agent 将“代码”不仅视为一种输出文本格式，而是将其作为一种可执行的、确定性的状态环境。

  • 核心机制：利用代码解释器（如 Python Sandbox）提供确定性的执行反馈（Traceback / Stdout），驱动模型进行迭代优化。
  • 重点范式 (如 Self-debug, SWE-agent)：
    • Self-debugging：模型生成代码后，直接将其送入沙盒执行。如果报错，模型会捕获错误堆栈信息作为新的 Observation，再次推断并修改代码。
    • 逻辑流转：状态转移可表示为 $C_{t+1} = \pi_\theta(C_t \mid \text{Execution_Result}(C_t))$，这是一个极其高效的强化学习过程，其 Reward 信号（通过/失败/报错日志）比传统的自然语言反馈更加精准和稠密。
    • 工程挑战：如 SWE-agent 所展示的，此类系统在处理真实仓库级任务时，需要应对极长的上下文。随着交互轮数的增加，如何优雅地管理 KV Cache 并在长序列中保持核心意图的 Attention 权重，是底层架构设计的一个关键点。
  1. Observation-based Agent (基于观察的智能体)

此类 Agent 侧重于在复杂多步环境中（如游戏、网页导航、生活模拟）进行马尔可夫决策过程（MDP）。它强调规划与记忆。

三种核心子类：

  • ReAct (Reasoning and Acting)：
    • 逻辑：将内部推理与外部动作交织。其轨迹可以表示为 $\tau = (s_1, t_1, a_1, o_1, s_2, t_2…)$。Thought 迫使模型在行动前进行显式的中间状态推导，有效缓解了幻觉和错误累积。
  • Reflexion (反思机制)：
    • 逻辑：一种基于语言的强化学习。在任务失败后，模型生成一段自然语言的反思作为上下文补充到下一次尝试中：$a_{t+1} \sim \pi(a \mid x, \text{memory}_{reflection})$。
  • Memory-based Agent (记忆智能体)：
    • 以 Generative Agents 为代表。引入了 Record（记录） -> Retrieve（检索） -> Reflect（反思） 的长期记忆机制。它将海量历史交互转化为高维度的洞察，使得 Agent 的行为具备时间连贯性。
  1. RAG Agent (检索增强智能体)

传统的 RAG 只是一个静态的“检索-阅读”流水线。而 RAG Agent 则将其升级为主动的、自适应的动态网络。

  • Standard RAG：$P(y \mid x) \approx P(y \mid x, z)$，其中 $z$ 是从向量数据库中检索出的 Top-K 文档。
  • Iterative / Active RAG (如 FLARE)：
    • 机制：前向主动检索。当模型在生成过程中对其预测的下一个 Token 或短语的置信度 $P(y_t \mid y_{<t}, x)$ 低于设定阈值 $\tau$ 时，主动触发检索操作，获取新知识后再继续生成。
  • Self-RAG (自我反思 RAG)：
    • 机制：通过在训练阶段（如 SFT 或 DPO 对齐阶段）向模型注入特定的 Reflection Tokens（例如 [Retrieve], [Relevant], [Supported]）。
    • 逻辑：这使得模型在推理时能够自主判断是否需要检索、检索到的文档是否相关、生成的答案是否有依据支撑。这相当于将一个微型的 LLM-as-judge 机制内置到了模型的自回归生成过程中，极大提高了输出的忠实度。

智能体系统分类

从结构上分类

1、工作流：通过预设的逻辑路径（如 IF-ELSE、编排引擎等）驱动，逻辑具有高度确定性。

  • 工作流 1：提示链 Prompt Chaining

Prompt Chaining 适合将复杂任务拆解为多个步骤，每个步骤由一个 LLM 调用完成，输出作为下一个步骤的输入。这种模式增加了系统的透明度和可控性，同时降低了单次 LLM 调用的复杂度。

适用场景：当任务可以明确拆解为多个顺序完成的子任务时。例如撰写长篇文章，先让模型生成大纲，确认后再分别生成每个段落；或者先进行信息提取，再根据提取的信息进行问答。

优势：

提高系统稳定性和可控性，每一步都可以进行 Prompt 优化。

便于 Debug 和调优，可以清晰定位是哪一步的输出导致了最终结果的错误。

  • 工作流 2：路由 Routing

Routing 模式引入了一个路由器，负责将输入分发给不同的处理单元。每个处理单元可以是一个特定领域的 LLM 或专门的工具。这种模式提高了系统的效率和灵活性。路由器本身也是一个 LLM，负责根据输入内容和任务需求决定分发策略。

  • 工作流 3：并行 Parallelization

并行模式下，一个输入会同时传递给多个处理单元（如不同的 LLM 或者不同的 Prompt），并在最后将结果进行汇总。

Sectioning（分块）：将任务分解成多个独立的部分，并行处理。

Voting（投票）：同一个任务由多个独立的 Worker 并行执行，根据多数投票或其他机制选出最终结果。

适用场景：对于可以通过分块并行处理来提高效率的任务，或通过多路并行投票来提高结果可靠性的场景。比如审查一份长代码，可以将代码分成多个函数并行检查。在复杂的分析任务中，不同的专家 Agent（如数据分析师、行业研究员等）可以并行给出分析意见。

优势：

Sectioning：显著提升系统运行效率，特别是对于可以拆解且子任务之间没有强依赖关系的情况。同时也可以绕过部分模型对于超长文本输入限制的问题（例如将长文本分段后分别提取摘要）。

Voting：利用“群体智慧”，提升结果的准确率和鲁棒性，适用于容错率极低的场景。

  • 工作流 4：编排器-工作者 Orchestrator-Workers

在 Orchestrator-Workers 模式下，一个中央的 Orchestrator 负责将任务分配给多个 Workers，并协调它们的工作。

适用场景：当任务非常复杂，且包含多个相互依赖的子任务时。Orchestrator 可以根据任务的进度和 Workers 的反馈动态调整计划。这种模式在复杂的软件开发、大型项目管理等领域有广泛应用。例如在开发一个软件项目时，Orchestrator 可以分配需求分析、代码编写、测试等任务给不同的 Worker Agent。

优势：

可以处理极度复杂的、包含动态依赖关系的任务。

系统的扩展性强，可以随时增加新的 Worker 来扩展系统的能力。

  • 工作流 5：评估-优化器 Evaluator-Optimizer

在该模式中，一个生成器负责生成初步结果，一个评估器负责对结果进行评估并提供反馈，生成器根据反馈进行优化。

适用场景：当任务的结果需要满足特定的标准或质量要求时。例如在机器翻译、代码生成等领域。

Generator 负责生成初稿，Evaluator 负责审核。

如果没有通过审核，Evaluator 会给出具体的修改意见。

Generator 根据修改意见重新生成初稿，进入下一轮迭代。

优势：

能够显著提高生成结果的质量和可靠性，特别是在那些对“正确性”有明确标准的场景下（如代码生成是否能通过测试用例），形成了一个闭环的自我迭代过程，能够不断优化结果。

2、自主智能体：LLM 动态决定操作序列与工具，具有“思考”能力，面对复杂未知场景表现更好，但存在一定的不确定性。

由模型完全控制运行过程：规划、反思、工具调用等均由大模型动态决策。其工作流不是预先设定好的，而是根据当前状态和目标实时生成的。适用于开放式任务，不需要人工干预，大语言模型充当“大脑”进行决策。

在此模式中，大语言模型决定控制流：包含它所需的步骤、是否需要循环迭代等。

智能体会在完成一个操作后重新思考“我接下来应该做什么？”并持续进行环境交互，直到达成目标。

优势在于灵活，面对未知场景适应能力强；劣势在于过程不可控，如果大模型能力不够容易陷入死循环。

2、单智能体应用

BabyAGI、AutoGPT、HuggingGPT等，通过设计不同的prompt和工作流，利用OpenAI模型或者huggingface上的模型，实现任务规划、任务执行、任务排序等功能。

3、多智能体应用

generative_agents, MetaGPT, GPT-researcher, STORM / Co-STORM，多智能体协作交流完成任务。

RL和Agent作为目前基座训练和应用最重要的两个方向，开发者们将 LLM 当作 Agent 来进行 RL 后训练，有望进一步提升其回答质量、交互表现，或在特定任务上进一步微调，获得更适合应用场景的行为；另一方面，LLM 也能帮助 RL，当 RL 游戏遇到输入的复杂信息，LLM 可以用其强大的表示与推理能力来预处理信息，或者充当奖励函数、世界模型等各种模块，让 RL Agent 更快地学会完成任务。

4、GAIR/ToRL

ToRL通过RL使LLM能够自主探索和改进工具使用策略，让LLM能够自主学习何时以及如何调用工具，减少对人类启发式工具调用模式的依赖。

5、OpenManus/OpenManus-RL

借鉴了RAGEN和RICO，并在此基础上进一步探索了新的算法架构、多样的推理范式、复杂的奖励策略以及丰富的后训练策略组合。

6、RAGEN

RAGEN通过MDP框架及自建环境“推理-交互最佳化”算法，解决了多轮交互和随机环境中的关键挑战；其进阶的优化策略进一步增强了模型在不同复杂任务中的稳定性和表现。

7、eleurent/RL-Agents

RL-Agents为研究人员提供了一个全面的框架来实现和测试多种先进的强化学习算法，包括值迭代、蒙特卡罗树搜索和深度Q网络等。
